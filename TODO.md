# Entregáveis e critérios — EcoGestor Web

## 1. Produto e conteúdo
- Criar uma experiência web interativa premium, não apenas uma landing page institucional, para o visitante ver, explorar, clicar, interagir, entender e se impressionar.
- Usar como fonte principal o Relatório Geral EcoGestor e usar a logo oficial enviada como referência de cores, identidade, formas, linguagem gráfica e estilo tecnológico sustentável.
- Não inventar números, estatísticas, funcionalidades inexistentes, validações, usuários, parceiros, integrações físicas em produção ou faturamento real. Identificar claramente proposta, protótipo, simulação, estimativa, meta ou evolução futura.
- Posicionar o EcoGestor como ecossistema digital que conecta empresas, cooperativas, catadores, ecopontos e compradores/parceiros; comunicar rastreabilidade, acessibilidade, inteligência e conexão.
- Explicitar a ideia “Uma plataforma. Diferentes jornadas.” Empresas/gestores: experiência principalmente Web/PC, gestão de resíduos, dashboard ESG, indicadores, relatórios, rastreabilidade, MTR, marketplace, operações e dados ambientais. Catadores: experiência principalmente mobile, oportunidades, geolocalização, ecopontos, rotas, marketplace, renda, materiais, histórico, EcoPontos, acessibilidade e treinamentos.

## 2. Hero, storytelling e jornadas
- Hero cinematográfico com logo, frase “Onde o resíduo deixa de ser descarte e passa a ser oportunidade.”, headline “A inteligência por trás de uma economia circular.”, texto curto e fundo orgânico/tecnológico com rede viva de pessoas e materiais.
- Microinteração inicial para “Resíduo → Dado → Conexão → Valor”, com progressão sutil ao rolar.
- Storytelling do problema como desconexão entre quem gera, coleta, transforma e compra; mostrar Empresa → Resíduo → Catador → Coleta → Cooperativa → Triagem → Comprador → Novo ciclo; depois revelar como EcoGestor conecta elos. Usar apenas dados comprovados no relatório.
- Jornada interativa “Cadastro → Match → Coleta → Entrega → Venda → Relatório”, cada etapa reagindo à entrada na tela; encerrar “Do resíduo ao dado. Do dado ao valor.”

## 3. Jornadas e demonstração do produto
- Interação “Quem está usando o EcoGestor?” com botões “Sou empresa”/“Sou catador”; alternar visualização web de gestão (resíduos, indicadores, ESG, MTR, marketplace, relatórios, CO₂ evitado) e representação mobile (renda, materiais, coletas, oportunidades, ecopontos, rotas, EcoPontos, acessibilidade).
- Demonstração mobile bonita com mockup de smartphone e representações de renda, materiais vendidos, coletas, impacto, EcoPontos e oportunidades. Referenciar protótipo real quando disponível; não simular resultados reais.
- EcoPontos: mapa esquemático alinhado à identidade, pontos selecionáveis e painel com nome, distância, materiais, horário, status e “Traçar rota” somente quando houver dados reais. Sem dados de localização inventados; se não houver dados, deixar claro que o mapa é uma demonstração interativa e não sugerir locais reais. Mostrar “Localização → Entrega → Registro → Valorização”.
- Balança: demonstração interativa 0,0 kg → adicionar material → 15,0 kg → papelão 15 kg → geração de identificação/código → bipagem → registro. Rotular permanentemente como simulação do fluxo proposto, sem afirmar conexão física em produção. Fluxo: resíduo → pesagem → código → bipagem → registro.
- Acessibilidade em seção de destaque, interface demonstrativa e opções de voz, leitura/retorno assistido, Libras, interface ampliada, linguagem simplificada e suporte do assistente, sem alegar disponibilidade implantada além do relatório.
- Voz: “Registrei 15 quilos de papelão.” → Material: Papelão; Peso: 15 kg; Data: agora; solicitar confirmação com botões grandes “Confirmar” e “Editar”. A interação é demonstração da experiência.
- Integrar Nico como elemento de apoio interativo que dá dicas, aponta e reage; não usar imagem/personagem decorativo. Imagem do Nico só será usada se material for fornecido; se não, apresentar Nico como interface/assistente sem inventar sua aparência.
- Rastreabilidade criativa: tocar em um material e revelar Origem → Pesagem → Coleta → Ecoponto/Cooperativa → Venda → Destinação; identificação final “Histórico registrado no EcoGestor” com ressalva se for demonstração.

## 4. Impacto, negócio e roadmap
- Seção de impacto com resíduos rastreados, catadores conectados, CO₂ evitado e oportunidades; usar somente números comprovados. Se forem projeções/metas, rotular; caso não haja números atuais comprovados, não inventar contadores.
- Modelo de negócio visual/ecossistêmico: SaaS B2B recorrente; possíveis taxas de marketplace; recursos analíticos e serviços. Não afirmar lucro ou faturamento real; projeção ≠ lucro.
- Timeline MVP: cadastro, gestão, marketplace, chat; evolução: insights, treinamentos, EcoPontos, acessibilidade; escala: integração física, APIs, IA preditiva, expansão territorial. Marcar como roadmap/proposta.
- Seção de vídeo/pitch com player integrado à identidade e moldura de dispositivo, sem iframe genérico. Como não foi fornecido vídeo, oferecer seleção local funcional para reproduzir arquivo escolhido, sem vídeo ou placeholder inventado.
- Comparação visual breve entre modelo tradicional (fragmentação, baixa rastreabilidade, dificuldade de conexão, pouca visibilidade, processos manuais) e proposta EcoGestor (conexão, rastreabilidade, dados, acessibilidade, inteligência, valorização).
- Final emocional: futuro da reciclagem começa na conexão; EcoGestor; “Tecnologia para conectar. Dados para transformar. Impacto para continuar.”; CTAs funcionais “Conhecer o protótipo”, “Explorar o EcoGestor”, “Ver o projeto”. QR Code apenas se disponível.

## 5. Design, responsividade e acessibilidade
- Produto tecnológico premium + sustentabilidade + impacto social; evitar template genérico, aparência WordPress, cards básicos, repetição quadrada, fundo branco genérico, gradientes aleatórios, dashboard administrativo, aparência artificial e efeitos sem propósito.
- Mobile-first real para smartphones, tablets, notebooks e desktops; no mobile: navegação simples, elementos grandes, legibilidade, gestos naturais e nenhuma seção quebrada/overflow horizontal/imagem deformada.
- Logo como referência principal; paleta verde sustentável, azul profundo, neutros escuros e pequenos acentos luminosos; alternar seções claras e escuras conforme narrativa.
- Animações modernas com propósito (parallax sutil, reveal, contadores apenas se factuais, estados, transições, linhas/partículas/mapa); leves e compatíveis com `prefers-reduced-motion`; sem animações excessivas ou loading desnecessário.
- Acessibilidade do próprio site: contraste, teclado, foco visível, aria-labels, alt text, fontes legíveis, alvos grandes e semântica HTML.
- Usar imagens estrategicamente; evitar imagens falsas como registro real do projeto; imagens externas só de fontes adequadas. Não deformar logo nem dispositivos.

## 6. Tecnologia e entrega
- Implementar arquitetura simples React + Vite (ou equivalente moderno adequado) e componentes reutilizáveis. Organizar `src/components`, `src/sections`, `src/assets`, `src/data`, `src/styles`.
- Preparar `package.json`, README, favicon/logo, `.gitignore`, assets locais, rotas compatíveis com Vercel, caminhos relativos/portáveis, sem segredos ou dependência de arquivos locais exclusivos.
- `npm install`, `npm run dev` e `npm run build` devem funcionar; instalar dependências, executar build e corrigir erros.
- Antes do ZIP, verificar responsividade em 360, 390, 430, 768, 1280 e 1440 px; ausência de cortes, sobreposição e overflow; mapa, controles, navegação, interações e links; imagens; ausência de referências à Manus, placeholders, texto de demonstração e elementos quebrados.
- Entregar o projeto completo e ZIP `ecogestor-site-premium.zip`, pronto para VS Code, GitHub e Vercel, incluindo breve instrução de deploy: `npm install`, `npm run dev`, `npm run build`.
- Verificar visualmente: primeira tela marcante, identidade presente, experiência mobile e desktop, storytelling, demonstração do mapa, balança, rastreabilidade, app do catador, acessibilidade, Nico, voz, Libras, jornadas diferenciadas, animações úteis, números corretos, projeções identificadas, modelo de negócio, roadmap, player incorporável, CTA final, sem invenções e build/ZIP íntegros.
